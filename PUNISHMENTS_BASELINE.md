### Pre-existing gaps

- A Discord-ID moderator can get effective `is_moderator: true` from `/api/auth/me` while their database role stays `member`. The mobile tab consumes the role field and hides Mod for that profile.
- A session authorized by [`verifyModeratorAuthorization`](src/lib/auth.ts) can execute `approve_cooldown` and the schedule/timezone fields of `edit_member` in `/api/mod` without independently supplying the master passcode. The regular-member schedule route itself still queues member edits and requires the master passcode for its instant override. Phase 1 needs explicit authorization coverage for both moderator actions.

## Strike ledger and monthly counter writers

| Writer | Current behavior and Phase 2 impact |
| --- | --- |
| SQL schema and migrations | [schema.sql](supabase/schema.sql) creates the ledger keyed by `(target_member_id, sleep_cycle_date)`, with a member-delete cascade. Both it and [the accountability migration](supabase/migrations/20261119_dispatch_accountability.sql) define the transactional `apply_nightly_strike` RPC. It locks the member, verifies the expected record type and check-in evidence, upserts a strike or Metastrike or deletes a cleared row, and writes both counter aliases plus `strike_cycle_month`. It returns `already_at_max_strikes` at three and rejects earlier counter months. Remove both forms of the regular counter checks from existing schemas as applicable (inline/default-named and explicit `check_strikes_*_range` constraints). [The earlier weekly migration](supabase/migrations/20261113_add_weekly_schedule.sql) added counter columns that may predate the checks. Keep the separately enforced three-pass allowance. |
| Scheduled automatic strikes | [Cron API](src/app/api/cron/dispatch-notifications/route.ts) calls [cronDispatcher](src/lib/cronDispatcher.ts) for eligible current and prior cycles. It reads durable state, uses `issueAutomaticBedtimeStrike`, and fences logging and notifications by cycle. In configured Supabase this calls the RPC. The local path checks `>= 3` first and updates counters and the nightly row through the helpers. A capped cycle can still be finalized as `not_issued`. Dry run reports candidates before the RPC's cap and transaction checks. Wake-up, check-in, and nag routes supply or consult cycle evidence and have no strike write. |
| Metastrike writers | [strikes.ts](src/lib/strikes.ts) implements `useProactiveMetastrike` and `convertStrikeToMetastrike`, called by the Metastrike API. Configured Supabase uses the RPC for both. The offline path updates counters then calls `saveNightlyStrikeLog`. A conversion changes the same dated row and adjusts both counters. The next scheduled bedtime limits a member replacement. For all RPC calls, the TypeScript wrapper passes the member's local month at write time as `p_month` separately from the stored cycle date. SQL rejects a supplied month older than the current counter month. Phase 2 needs to reconcile by the dated cycle so delayed strikes and cross-month corrections affect the earned month. |
| Moderator corrections | `adjust_strikes` calls `modAdjustStrikes`, clamps both totals in the route, and writes absolute totals via `updateMemberStrikeCounts` with no dated evidence. `clear_strike_log` calls `modClearStrikeLog`, using the RPC in Supabase and the counter helper plus `deleteNightlyStrikeLog` in the fallback. [The drawer](src/components/ModDrawer.tsx) calls both, clamps strike adjustments locally, and exposes controls based on the current cap. Use dated, auditable corrections and reconcile the affected month. Permanent member deletion and demo purges can remove ledger rows by cascade. |
| Lazy reset, alias repair, and stores | `resolveMemberStrikeCounts` can write a forward reset or repair aliases through `updateMemberStrikeCounts`, even on read paths such as roster, mod list, strike details, and sleep history. It uses [`checkMonthlyStrikeReset`](src/lib/sleepEngine.ts), values from persisted columns, dated logs and memory when available. Review its regular-strike clamp, the clamp in `updateMemberStrikeCounts`, and the fallback merge clamp in `getMonthlyStrikeCountsBatch`. [db.ts](src/lib/db.ts) mirrors strike and Metastrike aliases in its safe-update compatibility paths. The `strikes.ts` fallback stores counters and nightly rows separately; the direct save/delete helpers also contain DB branches but the normal configured write flows use the RPC. `reset_monthly_strikes()` in the schema is a legacy bulk UTC writer with no in-repo invoker or job. Verify external jobs before replacing it. |
| New rows and defaults | New Discord onboarding explicitly initializes counters to zero and sets a month using UTC. Manual moderator creation and demo writes use schema counter defaults. Preserve valid dated history on upgrade; the old aggregate-only adjustments and counter discrepancies need review for the November seed. |
